# TablePro Fyne · 数据库查询客户端

基于 [TableProGo](../../README.md) 数据库逻辑实现的 **原生 GUI 数据库查询客户端**，
使用 [Fyne](https://fyne.io/)（纯 Go 桌面 UI）构建，不依赖 Webview / Wails 前端。

## 功能

- **多数据库支持**：MySQL、PostgreSQL、SQLite、SQL Server、Oracle
- **连接管理**：新建 / 编辑 / 测试 / 删除连接，密码使用 Windows DPAPI 加密保存
  （复用项目原有的 `connections.json` 与加密格式）。macOS / Linux 没有 DPAPI
  等价物，也不为此引入密钥串依赖：密码按明文写进 `connections.json`，
  文件权限固定 `0600`（`persist` 会重设，覆盖别的工具留下的宽松权限），
  连接对话框底部明示这条警告（`TestSecretStorageWarning` /
  `TestConnectionsFileStaysPrivate`）。要在非 Windows 上真正加密，得单独接
  macOS Keychain 或 Linux libsecret，需要能在对应平台实机验证时再做
- **传输加密**：连接对话框的「加密」下拉按引擎给出各自的词汇表。SQL Server
  默认 `encrypt=true` + `TrustServerCertificate=false`（加密并校验证书），
  另两项是「加密，信任服务器证书（自签）」和「不加密」；存量连接里空的
  SSL 值因此改为按加密+校验处理，要走明文必须显式选「不加密」。
  本项目的 go-mssqldb 只解析 `disable`/`true`/`false`，`strict`、`require`
  会让驱动报 ParseBool 错，所以列表里不提供（`TestMssqlDSNReachesTheDialer`
  钉住这一点）。MySQL 只在选「加密」时打开 TLS，PostgreSQL 用
  `disable`/`prefer`/`require`/`verify-ca`/`verify-full`
- **查询编辑器**：多行 SQL 输入，支持 `Ctrl+Enter` / `Cmd+Enter` 执行，
  关键字 / 库名 / 表名自动补全，可限制返回行数；
  支持多语句脚本（按引号/注释感知的方式切分，逐条执行、失败即停并报出序号）；
  `Ctrl+O` / `Ctrl+S`（或标签操作条上的「打开脚本 / 保存脚本」）读写 `.sql` 文件，
  保存时统一为 LF，载入超过 8MB 或含 NUL 的文件会被拒绝
- **结果表格**：动态列宽，表头显示列名与类型（点击排序），错误信息展示在状态栏；
  单元格栏内置「在结果中搜索」——输入片段即时高亮全部命中并定位首个，
  `Enter` 下一个、`Shift+Enter` 上一个（循环），命中计数 `n/N`，换结果自动清空
- **网格内编辑**（对照 TablePro）：`SELECT * 单表` 结果可直接编辑——
  编辑单元格（外键列提供引用表候选下拉）、插入行、删除行，保存前预览生成的
  UPDATE / INSERT / DELETE 语句，确认后在单个事务内提交（任一语句未命中
  行则整体回滚）。改动未保存时排序与翻页直接拒绝并在状态栏说明原因；执行新查询
  会先弹确认（新结果会替换网格、编辑队列随之清空），点「取消」则改动原样保留
- **列过滤**：按列多条件 AND 过滤（等于 / 比较 / 包含 / IS NULL），
  生成的 WHERE 语句填入编辑器，透明可改
- **表操作**：结构树中右键表/视图 → 删除 (DROP) / 清空 (TRUNCATE) /
  重命名 (RENAME)，语句按方言渲染、执行前确认并记入历史
- **新建表**：右键数据库/模式节点 →「新建表」，按方言生成最小
  `CREATE TABLE` 草案（MySQL `AUTO_INCREMENT`、PG `BIGSERIAL`、
  SQL Server `IDENTITY`、Oracle `GENERATED BY DEFAULT AS IDENTITY`、
  SQLite `AUTOINCREMENT`，PG/SQL Server 带上该节点的 schema，空则用引擎默认
  的 `public`/`dbo`），开成标题为「新建表 ●」的新标签并自动切到该库——
  表名和字段由你改，语句不自动执行
- **快速打开**：`Ctrl+P`（或结构页「搜索」按钮）输入表名片段，回车跨库搜索
  表/视图，点击结果自动切库、展开结构树、选中并填入 SELECT 预览
- **表结构查看**：结构树右键表/视图 →「查看结构」，字段（类型/可空/键/默认值/
  注释）、索引（类型/唯一性/字段）、外键（本表字段 / 引用表（按方言限定）/
  引用字段 / ON DELETE / ON UPDATE）与 DDL（重构的 CREATE TABLE + 索引/外键，
  一键复制）分页展示
- **导出**：CSV / JSON / INSERT 脚本（.sql，需单表 SELECT *）/
  Excel（.xlsx，数值与日期为真实类型单元格，冻结表头、自适应列宽）
- **结构浏览**：左侧树形浏览 数据库 → 模式 → 表/视图（过滤框实时筛选），
  点击表自动生成 `SELECT * FROM …` 预览，右键可 浏览数据（直接出结果）/
  查看结构 / 删除 / 清空 / 重命名
- **库过滤**：连接对话框的「库过滤(包含)」/「库过滤(排除)」两栏用 SQL-LIKE 式
  掩码隐藏结构树里的库——`%` 与 `*` 匹配任意串、`_` 匹配单个字符、不分大小写；
  排除优先于包含，包含留空＝显示所有没被排除的库，两栏都空＝显示全部；
  每行或每个逗号一个模式，重复与空行自动丢掉。保存即生效：`Databases` 取的是
  **落盘配置**里的过滤条件，而不是连接建立时那份快照（活动连接的 `Config`
  处处无锁读，改它会和在跑的查询竞态），对话框也因此顺手重拉结构树和数据库下拉
  （`TestFilterFollowsSavedConfig`）。它只影响导航，SQL 照样打得到整台服务器；
  SQLite 只有一个库，两栏置灰
- **行数上限**：100 / 500 / 1000 / 5000 / 无限制
- **结果分页浏览**：勾选工具条的「分页浏览」后，单条 SELECT 按页取数——每页
  10 / 20 / 50 / 100 / 200 / 500 行，翻页时重新查库（服务端行窗口：
  MySQL/PG/SQLite 的 `LIMIT…OFFSET`、SQL Server/Oracle 的
  `OFFSET…FETCH NEXT`，前者无 ORDER BY 时自动补 `ORDER BY (SELECT NULL)`），
  不取总数、不预读整表；网格上方的翻页条显示「第 X 页 · 本页 N 行」，
  整页即视为可能还有下一页、短页即末页（下一页置灰）。改每页行数会立刻重取
  第 1 页；翻页不写历史记录、有未保存的网格更改时被拒绝；分页开启时
  「行数上限」置灰（行窗口就是上限）。自带行窗口（LIMIT/TOP/OFFSET/FETCH/
  ROWNUM）的语句按原样执行并说明未分页。**注意：结果内搜索与表头排序只作用于
  当前页**
- **翻页稳定排序**：没有 ORDER BY 的语句，行窗口不保证各行被稳定分给某一页——
  上一页出现过的行可能在下一页重复，也可能被跳过。因此分页时：语句自带外层
  ORDER BY 的原样使用；单表 `SELECT *` 自动补上主键排序（复合键按全部键列排序，
  翻页条写明「已按主键 … 排序」，键太长只报列数以免挤掉翻页按钮）；
  其余形状（投影、聚合、无主键）不猜排序，翻页条标 ⚠ 并说明可能重复/漏行
- **快捷键**：`Ctrl/Cmd+Enter` 执行、`Ctrl/Cmd+N` 新标签、`Ctrl/Cmd+W` 关闭当前标签、
  `Ctrl/Cmd+1…9` 切到第 N 个标签（超出标签数不环绕、不动作）、`Ctrl/Cmd+P` 快速打开、
  `Ctrl/Cmd+O` / `Ctrl/Cmd+S` 读写脚本——光标在编辑器、过滤框或搜索框内同样生效
  （Fyne 会把快捷键先交给聚焦控件，故每个输入框都查同一张 `ui_keys.go` 绑定表；
  `Ctrl+C` 除外，输入框保留自身复制语义）。工具条上的「快捷键」按钮列出全部组合键，
  说明文字与绑定同处登记，加一个绑定就多一行——只有 `Ctrl/Cmd+1…9` 那九个绑定
  共用一行，免得对话框被九行近乎重复的文字挤满

## 项目结构

```
fynequery/
├── go.mod                  # 独立 Go 模块（避免与根 Wails 模块冲突）
├── main.go                 # 程序入口：创建窗口并运行
├── clientstore.go          # Client→Store 薄包装：连接生命周期、外键缓存、XLSX 落盘
├── settings.go             # 界面状态持久化（主题/窗口/分割位/标签草稿）
├── ui.go                   # Client 状态与主布局（侧栏+主区装配）
├── ui_keys.go              # 快捷键表：bindKey 登记 + 各输入框共用 entryShortcut + 快捷键对话框
├── ui_connections.go       # 连接面板（下拉/连接/管理）
├── ui_connections_dialog.go# 连接新建/编辑对话框（SQLite 文件选择器、库过滤掩码）
├── ui_suggest.go           # SQL 补全控件：suggestEntry、词元定位、候选匹配
├── ui_editor.go            # SQL 编辑器编排：查询标签、行号槽、候选条、补全池
├── ui_script.go            # .sql 脚本打开/保存（流式读写 + 文件对话框）
├── ui_grid.go              # 结果网格模块：单元格状态、列宽、排序、复制、导出
├── ui_grid_search.go       # 结果集内搜索：扫描命中、Enter/Shift+Enter 跳转、高亮
├── ui_grid_edit.go         # 网格编辑队列与操作
├── ui_query.go             # 查询页装配与执行入口（runCurrent + runTracked 异步执行壳）
├── ui_paging.go            # 结果分页：分页开关、翻页条、按页重查、稳定排序判定
├── ui_filter.go            # 过滤条件对话框
├── ui_search.go            # 快速打开对话框
├── ui_structure.go         # 表结构查看器
├── ui_schema.go            # 结构导航渲染：行构件按 uid+外观记忆化，集合未变跳过重排
└── internal/db/            # 数据层（抽象屏障：编译器强制，不含任何 fyne 依赖）
    ├── db.go               # Store 内核：连接表/连接池/语句历史的唯一持有者 + 状态目录解析与一次性迁移
    ├── core.go             # 数据类型与常量（ConnConfig/QueryResult/…）
    ├── store.go            # 连接持久化（加载/保存/增删改）
    ├── store_connect.go    # 打开/测试连接、按库缓存连接池、DSN 构造
    ├── query.go            # 查询执行（SELECT/命令）、多语句脚本、标识符引用
    ├── paging.go           # 行窗口分页：可分页判定、PageSQL/WithOrderBy 渲染、ExecutePage 重查
    ├── dialect.go          # 引擎方言操作表：各引擎目录 SQL 集中于此
    ├── browse.go           # 结构浏览：数据库/模式/表（方言表的 apply-generic）
    ├── browse_columns.go   # 列元数据、索引聚合
    ├── changes.go          # 网格编辑引擎：UPDATE/INSERT/DELETE 生成与事务提交
    ├── exportsql.go        # 导出 INSERT 脚本
    ├── export.go           # CSV/JSON 导出
    ├── exportxlsx.go       # Excel 工作簿渲染（excelize，纯字节输出）
    ├── filters.go          # 列过滤条件 → WHERE 渲染
    ├── tableactions.go     # 表操作（DROP/TRUNCATE/RENAME）
    ├── fk.go               # 外键目录读取与引用表候选值
    ├── search.go           # 跨库对象搜索（快速打开）
    ├── ddl.go              # 从目录行重构 CREATE TABLE +「新建表」各方言建表草案
    ├── script.go           # 多语句脚本切分器
    ├── history.go          # 语句历史（记录/截断/持久化）
    ├── secrets_windows.go  # Windows DPAPI 密码加密（build:windows）
    └── secrets_other.go    # 非 Windows 平台明文存储（build:!windows）
```

分层规则：`internal/db` 只依赖标准库与驱动，UI 通过 `db.Store` 的导出方法访问
数据；界面控件、会话选择（当前连接/当前库）与各类缓存留在 `main`。新增引擎
只需在 `dialect.go` 的方言表中加一行。

## 构建与运行

要求：Go 1.22+、具备 CGO 的编译器（Windows 上可用 MinGW/TDM-gcc 等）。

```bash
cd fynequery
go mod tidy
go build -o fynequery.exe .
./fynequery.exe
```

提交前的门（装了 [Task](https://task.dev/) 时）：`task check`，即
`gofmt -l .` + `go vet ./...` + `go test -race ./...`。测试跑在
`TABLEPRO_STATE_DIR` 指向的临时目录里，不会写你真实的连接与历史。
本仓库没有配 Git 远端，所以放 GitHub Actions 工作流没有东西会执行它；
等真有远端再加。

## 使用说明

页面布局对照 TablePro Go：左侧单一侧栏——「导航」标题（＋新建连接）、连接
下拉与连接/断开、测试/编辑/删除、对象过滤框（实时筛选已加载对象）、结构树、
底部历史栏；主区为**多查询标签页**（每页独立编辑器，可新建/关闭，共享结果
网格），标签下工具栏为 数据库 → 执行（高亮）→ 快捷键 → 行数上限 + 分页浏览 →
导出 → 主题；结果网格上方是翻页条（只在分页时出现），底部为单元格栏与
状态/操作工具条。

其他要点：

- **异步连接与查询**：连接握手、表目录加载、SQL 执行均在工作线程进行，界面不冻结；执行中可点「取消」中断长查询（fyne 2.6+ 的 fyne.Do 调度回主线程）
- **线程归属**：当前连接 / 当前库 / 每页行数只归 UI 线程所有，工作线程拿的是启动时在 `c.mu` 内取到的快照；`TestQueryGoroutineUsesSessionSnapshot` 在 `go test -race` 下用一条慢查询 + 并发改写会话字段的守卫脚本钉住这条不变量
- **编辑器行号槽**：等宽 SQL 编辑器左侧带行号（禁用多行输入框实现，与编辑器同族同字号精确对齐）；长脚本在标签内滚动而非拉伸窗口，编辑时自动跟随光标行
- **查询标签**：多页独立编辑器（`Ctrl/Cmd+N` 新建、`Ctrl/Cmd+W` 关闭、
  `Ctrl/Cmd+1…9` 切到第 N 个），修改未执行的标签标题带 ● 标记、关闭前确认；
  切换标签时补全候选随活动页切换；关闭时各标签的 SQL 草稿与脏标记写入 `ui.json`，重启后完整恢复
- **主题**：工具栏可切 跟随系统/浅色/深色（即时生效并持久化）
- **历史写盘**：语句历史整份重写，但不是每执行一条就落盘——5 秒内连续执行只写一次，
  关窗时补齐剩下的尾巴（`TestHistoryWriteIsThrottled`）；进程被强杀最多丢这一个
  延迟窗口内的记录

1. **新建连接**：在侧栏顶部选择器旁点击「新建」，填写类型、主机、端口、账号等。
2. **测试**：点击「测试」验证连接参数。
3. **连接**：在下拉框选中连接后点击「连接」，侧栏中部会加载该库的结构树。
4. **查询**：在右侧编辑器输入 SQL（有自动补全），点击「执行」或按 `Ctrl+Enter`。
5. **浏览结构**：在侧栏结构树点击表名生成 SELECT 预览；右键表可查看结构 /
   删除 / 清空 / 重命名；右键数据库/模式点「新建表」拿方言建表草案；
   `Ctrl+P` 快速按名找表。服务器上的库多到翻不动时，在「编辑连接」的
   库过滤里写掩码（如包含 `APP*`、排除 `*_backup`）只留常用的那几个。
6. **编辑数据**：`SELECT * 单表` 结果可在网格底部工具条编辑单元格、插行、
   删行，确认后事务提交。
7. **翻页浏览大表**：勾选「分页浏览」，选好每页行数再执行 SELECT，用网格上方
   的上一页/下一页逐页读取（每页重新查库，不预读整表）。翻页条同时告诉你这一页
   的行序是否稳定：自动补了主键排序会写明，补不了会标 ⚠ 提醒可能重复/漏行。

## 说明

- 本模块为独立子模块，与根目录的 Wails 版本（`TableProGo`）互不影响，
  可并存于同一仓库。
- **状态文件位置**：`connections.json`、`history.json`、`ui.json` 放在
  `os.UserConfigDir()/TableProGo`（Windows 即 `%AppData%\TableProGo`），
  与根版本同一目录、同一格式，因此保存的连接两边共享；代价是历史文件也
  是共享的，两个客户端同时开着会互相覆盖对方内存里那份日志。首次启动会把
  旧版留在 exe 旁的同名文件**复制**进配置目录（原文件保留，删用户数据不是
  本程序的权利）；配置目录已有同名文件时以配置目录为准。`TABLEPRO_STATE_DIR`
  可整体改道（便携安装、测试隔离），`go test` 就是靠它不碰真实连接
  （见 `main_test.go`）。
- 连接握手、目录浏览与 SQL 执行都在工作线程进行，结果经 `fyne.Do` 调度回 UI
  线程刷新；长查询可点「取消」中断，翻页取数走同一条异步路径。
