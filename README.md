# TablePro Fyne · 数据库查询客户端

基于 [TableProGo](../../README.md) 数据库逻辑实现的 **原生 GUI 数据库查询客户端**，
使用 [Fyne](https://fyne.io/)（纯 Go 桌面 UI）构建，不依赖 Webview / Wails 前端。

## 功能

- **多数据库支持**：MySQL、PostgreSQL、SQLite、SQL Server、Oracle
- **连接管理**：新建 / 编辑 / 测试 / 删除连接，密码使用 Windows DPAPI 加密保存
  （复用项目原有的 `connections.json` 与加密格式）。macOS / Linux 没有 DPAPI
  等价物，也不为此引入密钥串依赖：密码按明文写进 `connections.json`，
  文件权限固定 `0600`（`persist` 会重设，覆盖别的工具留下的宽松权限），
  连接对话框底部明示这条警告（`TestSecretStorageWarning` /
  `TestConnectionsFileStaysPrivate`）。要在非 Windows 上真正加密，得单独接
  macOS Keychain 或 Linux libsecret，需要能在对应平台实机验证时再做
- **传输加密**：连接对话框的「加密」下拉按引擎给出各自的词汇表。SQL Server
  默认 `encrypt=true` + `TrustServerCertificate=false`（加密并校验证书），
  另两项是「加密，信任服务器证书（自签）」和「不加密」；存量连接里空的
  SSL 值因此改为按加密+校验处理，要走明文必须显式选「不加密」。
  本项目的 go-mssqldb 只解析 `disable`/`true`/`false`，`strict`、`require`
  会让驱动报 ParseBool 错，所以列表里不提供（`TestMssqlDSNReachesTheDialer`
  钉住这一点）。MySQL 只在选「加密」时打开 TLS，PostgreSQL 用
  `disable`/`prefer`/`require`/`verify-ca`/`verify-full`
- **查询编辑器**：多行 SQL 输入，支持 `Ctrl+Enter` / `Cmd+Enter` 执行，
  关键字 / 库名 / 表名自动补全，可限制返回行数；
  支持多语句脚本（按引号/注释感知的方式切分，逐条执行、失败即停并报出序号）；
  `Ctrl+O` / `Ctrl+S`（或标签操作条上的「打开脚本 / 保存脚本」）读写 `.sql` 文件，
  保存时统一为 LF，载入超过 8MB 或含 NUL 的文件会被拒绝
- **结果表格**：动态列宽，表头显示列名与类型（点击排序），错误信息展示在状态栏；
  单元格栏内置「在结果中搜索」——输入片段即时高亮全部命中并定位首个，
  `Enter` 下一个、`Shift+Enter` 上一个（循环），命中计数 `n/N`，换结果自动清空
- **网格内编辑**（对照 TablePro）：`SELECT * 单表` 结果可直接编辑——
  编辑单元格（外键列提供引用表候选下拉）、插入行、删除行，保存前预览生成的
  UPDATE / INSERT / DELETE 语句，确认后在单个事务内提交（任一语句未命中
  行则整体回滚）。改动未保存时排序与翻页直接拒绝并在状态栏说明原因；执行新查询
  会先弹确认（新结果会替换网格、编辑队列随之清空），点「取消」则改动原样保留
- **列过滤**：按列多条件 AND 过滤（等于 / 比较 / 包含 / IS NULL），
  生成的 WHERE 语句填入编辑器，透明可改
- **表操作**：结构树中右键表/视图 → 删除 (DROP) / 清空 (TRUNCATE) /
  重命名 (RENAME)，语句按方言渲染、执行前确认并记入历史
- **新建表**：右键数据库/模式节点 →「新建表」，按方言生成最小
  `CREATE TABLE` 草案（MySQL `AUTO_INCREMENT`、PG `BIGSERIAL`、
  SQL Server `IDENTITY`、Oracle `GENERATED BY DEFAULT AS IDENTITY`、
  SQLite `AUTOINCREMENT`，PG/SQL Server 带上该节点的 schema，空则用引擎默认
  的 `public`/`dbo`），开成标题为「新建表 ●」的新标签并自动切到该库——
  表名和字段由你改，语句不自动执行
- **快速打开**：`Ctrl+P`（或结构页「搜索」按钮）输入表名片段，回车跨库搜索
  表/视图，点击结果自动切库、展开结构树、选中并填入 SELECT 预览
- **表结构查看**：结构树右键表/视图 →「查看结构」，字段（类型/可空/键/默认值/
  注释）、索引（类型/唯一性/字段）、外键（本表字段 / 引用表（按方言限定）/
  引用字段 / ON DELETE / ON UPDATE）与 DDL（重构的 CREATE TABLE + 索引/外键，
  一键复制）分页展示
- **导出**：CSV / JSON / INSERT 脚本（.sql，需单表 SELECT *）/
  Excel（.xlsx，数值与日期为真实类型单元格，冻结表头、自适应列宽）
- **结构浏览**：左侧树形浏览 数据库 → 模式 → 表/视图（过滤框实时筛选），
  点击表自动生成 `SELECT * FROM …` 预览，右键可 浏览数据（直接出结果）/
  查看结构 / 删除 / 清空 / 重命名
- **库过滤**：连接对话框的「库过滤(包含)」/「库过滤(排除)」两栏用 SQL-LIKE 式
  掩码隐藏结构树里的库——`%` 与 `*` 匹配任意串、`_` 匹配单个字符、不分大小写；
  排除优先于包含，包含留空＝显示所有没被排除的库，两栏都空＝显示全部；
  每行或每个逗号一个模式，重复与空行自动丢掉。保存即生效：`Databases` 取的是
  **落盘配置**里的过滤条件，而不是连接建立时那份快照（活动连接的 `Config`
  处处无锁读，改它会和在跑的查询竞态），对话框也因此顺手重拉结构树和数据库下拉
  （`TestFilterFollowsSavedConfig`）。它只影响导航，SQL 照样打得到整台服务器；
  SQLite 只有一个库，两栏置灰
- **行数上限**：100 / 500 / 1000 / 5000 / 无限制。语句自带行窗口、或形状无法安全
  注入上限（SQL Server 的 `WITH … SELECT` 就是：`TOP` 插不进去）时，SQL 按原样执行，
  状态栏在结果行数后面写明「行数上限 N 未生效」而不是悄悄多给行
  （`TestRowCapDeclinedIsReported`，含上限真的绑上时不得报未生效的负对照）；
  上限真的绑上且砍掉了答案时，写明「已达行数上限 N，还有更多行未取出」，
  免得刚好一屏的行数被当成整张表（`TestRowCapTruncatedIsReported`）
- **结果分页浏览**：勾选工具条的「分页浏览」后，单条 SELECT 按页取数——每页
  10 / 20 / 50 / 100 / 200 / 500 行，翻页时重新查库（服务端行窗口：
  MySQL/PG/SQLite 的 `LIMIT…OFFSET`、SQL Server/Oracle 的
  `OFFSET…FETCH NEXT`，前者无 ORDER BY 时自动补 `ORDER BY (SELECT NULL)`），
  不取总数、不预读整表；网格上方的翻页条显示「第 X 页 · 本页 N 行」，
  整页即视为可能还有下一页、短页即末页（下一页置灰）。改每页行数会立刻重取
  第 1 页；翻页不写历史记录、有未保存的网格更改时被拒绝；分页开启时
  「行数上限」置灰（行窗口就是上限）。自带行窗口（LIMIT/TOP/OFFSET/FETCH/
  ROWNUM）的语句按原样执行并说明未分页；多语句脚本也一样只说明不翻页——脚本的
  结果是整份取的，把末条语句说成「第 1 页」会让下一页重演屏幕上已有的行
  （`TestScriptResultIsNotClaimedAsAPage`）。**注意：结果内搜索与表头排序只作用于
  当前页**
- **翻页稳定排序**：没有 ORDER BY 的语句，行窗口不保证各行被稳定分给某一页——
  上一页出现过的行可能在下一页重复，也可能被跳过。因此分页时：语句自带外层
  ORDER BY 的原样使用；单表 `SELECT *` 自动补上主键排序（复合键按全部键列排序，
  翻页条写明「已按主键 … 排序」，键太长只报列数以免挤掉翻页按钮）；
  其余形状（投影、聚合、无主键）不猜排序，翻页条标 ⚠ 并说明可能重复/漏行
- **快捷键**：`Ctrl/Cmd+Enter` 执行、`Ctrl/Cmd+N` 新标签、`Ctrl/Cmd+W` 关闭当前标签、
  `Ctrl/Cmd+1…9` 切到第 N 个标签（超出标签数不环绕、不动作）、`Ctrl/Cmd+P` 快速打开、
  `Ctrl/Cmd+O` / `Ctrl/Cmd+S` 读写脚本——光标在编辑器、过滤框或搜索框内同样生效
  （Fyne 会把快捷键先交给聚焦控件，故每个输入框都查同一张 `ui_keys.go` 绑定表；
  `Ctrl+C` 除外，输入框保留自身复制语义）。工具条上的「快捷键」按钮列出全部组合键，
  说明文字与绑定同处登记，加一个绑定就多一行——只有 `Ctrl/Cmd+1…9` 那九个绑定
  共用一行，免得对话框被九行近乎重复的文字挤满

## 构建与运行

要求：Go 1.25+（口径是 `go.mod` 里的 `go 1.25.0`，CI 用 `go-version-file` 读它；
更旧的 Go 只有在 `GOTOOLCHAIN=auto` 且能联网时才会自己下去一版工具链，
`local` 就直接拒）、具备 CGO 的编译器（Windows 上可用 MinGW/TDM-gcc 等）。

```bash
git clone <本仓地址>
cd fynequery
go mod tidy
go build -ldflags "-H=windowsgui" -o fynequery.exe .
./fynequery.exe
```

`-H=windowsgui` 不是可选的美化：不带它，产物的 PE 子系统是 `Windows CUI`
（`objdump -p` 实测 `00000003`），双击会先弹一个控制台窗；带上它是
`Windows GUI`（`00000002`）。这个 flag 只对 Windows 链接有效，所以
`Taskfile.yaml` 把它放在 `platforms: [windows]` 的分支里，Linux/macOS 走另一条
`go build`（`task build` 会按当前平台挑对应那条）。

不需要初始化脚本。共享逻辑住在兄弟仓 `TableProGo` 里，已下沉成两个独立模块并
打了 tag：`github.com/Ben-guanzhi/TableProGo/tableprosql`（各方言 SQL 文本与
`ColumnType` 判定）和 `github.com/Ben-guanzhi/TableProGo/tableproxlsx`（Excel
渲染）。本仓 `go.mod` 直接 `require` 它们的版本，**不带 `replace`**，所以单独
clone 就能构建。早先这里用相对 `replace` 指 `../tableprosql`，单独 clone 会因
目录不存在而失败，得靠 `setup.sh` 先把父仓克隆到旁边——那套脚本已随 tag 化删除。

代价是共享代码的改动要发 tag 才轮得到这里：改完 `tableprosql`/`tableproxlsx`
在父仓打 tag（tag 名必须带子目录前缀，如 `tableprosql/v0.1.0`，这是 Go 对
子目录模块的要求），本仓再 `go get` 升到那一版。`go list -m all` 随时能看到本
仓实际吃的是哪一版，所以两个客户端不会静默漂移到各不一样的共享代码。

提交前的门（装了 [Task](https://task.dev/) 时）：`task check`，即
`gofmt -l .` + `go vet ./...` + `go test -race ./...`。测试跑在
`TABLEPRO_STATE_DIR` 指向的临时目录里，不会写你真实的连接与历史。
`.github/workflows/ci.yml` 跑同一套门，另加 `go mod tidy` 无差异校验与一次
`go build`——它同时就是「tag 分发可用」的持续证明；同文件还有一个 `contract`
job，见下。

### 写路径的事务矩阵

`ApplyChanges` 是本包唯一往服务器写数据的地方，它的承诺是「要么全落，要么全不
落」。这句没法由 `changes_test.go` 那些纯渲染断言证明，只有一个真会回滚的事务说
得算，所以 [internal/db/changes_apply_test.go](file:///D:/tools/db/fynequery/internal/db/changes_apply_test.go)
用 SQLite 文件库跑这张矩阵（9 个测试、15 条 RUN，不需要任何 server）：三种改动
共用一个事务提交；第 2 条语句撞 UNIQUE 时，第 1 条已经写下的行也不留下；第 2 条
匹配不到行时同样回滚，而把同一队列指向还在的那两行必须成功——否则守卫会因为
「谁都匹配不到」而假绿；空队列、键不在结果里、未知 kind、类型不符、表不存在这
五种拒绝必须发生在开事务之前；回滚之后还能再存一次；断开时拒绝、重连后落地。
断言一律回读表格内容，不是只看客户端自己报的计数。

它抓到两处真问题：

1. `valueLiteral` 不认识 `int64`（也没有 go-sql-driver 会交来的 `uint64` 与
   `float32`），而网格是把读回来的那一行原样当 `Original` 交下来的
   （[ui_grid_edit.go:102](file:///D:/tools/db/fynequery/ui_grid_edit.go#L102)
   的 `collectChanges`）。三个驱动对整数列交的都是 `int64`（mattn/go-sqlite3 实测、
   lib/pq 的 `decode`、go-sql-driver 的 `readRow` 都读过源码确认），所以任何整数
   主键的 UPDATE/DELETE 都以 `unsupported value of type int64` 失败，「导出为
   INSERT 语句」同样失败。现在按各驱动真正交来的形状补齐
   （[internal/db/changes.go:270](file:///D:/tools/db/fynequery/internal/db/changes.go#L270)），
   并且写成整数而不是先转 float：超过 2^53 的键转成 double 就不再是那个键，
   WHERE 会指到别的行或哪也不指。根仓没有照搬这三个分支——它够不着：那边每个进
   `valueLiteral` 的值都过一遍 JSON（`json.NewDecoder(...).Decode(&body)` 解
   `[][]interface{}`，没有 `UseNumber()`），交回来的动态类型只会是 `float64`，
   实测见下面的「数字文本的精确路径」。
2. `ApplyChanges` 失败时返回一路累加到那儿的半截计数，跟它自己那句
   "nothing was committed" 相互矛盾；界面只显示错误，所以这个数没流到用户眼前，
   但一个说谎的返回值不该留在那里。现在失败一律返回 0
   （[internal/db/changes.go:568](file:///D:/tools/db/fynequery/internal/db/changes.go#L568)）。

顺带把 MySQL 连接设成 `ClientFoundRows`
（[internal/db/store_connect.go:126](file:///D:/tools/db/fynequery/internal/db/store_connect.go#L126)）：
驱动默认报的是「字节真的变了」的行数，把同一个值再存一次就是 0，会被那条
「匹配不到行」的守卫当成丢行而整批中止。参照系这边只测得动 SQLite：
`TestIdenticalValueUpdateCountsAsOneRow` 实测它报的是匹配到的那一行；PostgreSQL 与
MySQL 各自答什么，本地没有 server 可以问，所以这一半留给下面契约组的
「an unchanged value still counts the matched row」，由 CI 第一次真跑时回答。

负对照：把 `int64` 分支临时改成返回错误后，9 条测试变红；而
`TestInsertScriptBuilderMatchesTheOldRendererByteForByte` 依旧绿——新旧两个渲染器共用
同一个 `valueLiteral`，一起报错、一起返回空串，「逐字节相等」这条断言就看不见缺陷
了。原因写在
[internal/db/exportsql_test.go:81](file:///D:/tools/db/fynequery/internal/db/exportsql_test.go#L81)

### 数字文本的精确路径

同一条 2^53 的悬崖，另一侧是**文本**：单元格里敲进去的键与过滤框走的是
`valueLiteral` 的字符串分支，而它把文本 `ParseFloat` 之后再 `numberLiteral`——
double 只有 53 位尾数，用户拼对了键，服务端拿到的是另一个数。改前实测（表驱动
用例即这几条）：

| 文本 | 旧渲染 | 是用户写的吗 |
| --- | --- | --- |
| `9007199254740993` | `9007199254740992` | 差 1 |
| `18446744073709551615` | `18446744073709552000` | 差 1 |
| `18446744073709551616` | `18446744073709552000` | 差 1 |
| `-99999999999999999999` | `-100000000000000000000` | 同样差 1，只是差在高位 |
| `123456789012345678.90` | `123456789012345680` | 带小数点的那侧同一个悬崖，这次连整数部分都错了 |
| `0.1111111111111111111111` | `0.1111111111111111` | 后 10 位凭空抹掉 |
| `1.50` | `1.5` | 值相等，但用户写的标度保不住 |

危害不是「报错」而是**改错行**：夹具里 `9007199254740993` 与 `9007199254740992`
两行都在，旧路径把 UPDATE 落到了邻行，`ApplyChanges` 返回 applied=1、一句错误都
没有——连「匹配不到行」那道守卫都不会响，因为它匹配到了，只是不是那一行。这条
断言在两仓各有一份真库测试
（[internal/db/changes_apply_test.go:185](file:///D:/tools/db/fynequery/internal/db/changes_apply_test.go#L185)、
根仓 `../TableProGo/apply_test.go:159`）。

现在认得的形状是「一个可选符号、一串数字、至多一个小数点且点两侧都要有数字」，认得
就原样写（[internal/db/changes.go:193](file:///D:/tools/db/fynequery/internal/db/changes.go#L193)）：
64 位装得下的走 `ParseInt/ParseUint` 顺带把 `007`、`+7` 归一化，装不下的**照写数字**，
既不四舍五入也不由客户端拒绝——`DECIMAL(30,0)` 真装得下 20 位，而 `bigint` 会用自己
的 out-of-range 错误回答，那个错误响亮且点名列名，客户端没权限替服务端先把它舍掉。
（这里修正了我先前的提案「超 19 位就拒绝」：那会误伤合法的大 DECIMAL 列。）
小数那侧同样只认形状、不算数：`1.50` 原样出，`.5`、`1.`、`1e3` 仍走老路（依次渲染成
`0.5`、`1`、`1000`），`0x10`、`1.2.3` 仍被拒，文字列的 `007` 仍是 `'007'`。真库侧补了
一条 `NUMERIC(30,2)` 主键的用例
（[internal/db/contract_test.go:811](file:///D:/tools/db/fynequery/internal/db/contract_test.go#L811)）：
把 `123456789012345678.90` 和旧路径正好渲染出来的那个邻值 `123456789012345680.00` 一起
种进去，改前者只有前者能动——这条是带诱饵行的，只看渲染文本看不出危害。

负对照分两层。把字符串分支里这次调用短路（`false && exact`，等价于改回旧写法）：2 条
测试红，表驱动里红出的正是上面表格那 7 个数（前 4 行是整数那侧，这次一并重新量过），
另一条是真库夹具 `TestApplyChangesLocatesARowByKeyTypedAsText`。再把形状扫描关掉
（`allDigits` 的循环条件改成 `i < 0`，等于什么都认）：6 条红——`1e3` 的归一化没了，
`twelve` 与 `7x`、`0x10`、`7 7`、`1.2.3` 五道拒绝一起失效。没有这道扫描，数字列里任何
文本都会被当作**未加引号的字面量**发给服务端，这才是这道扫描真正挡的东西，注释里写明了。

根仓那边补的是同一份 helper（两仓 `exactNumberLiteral` + `allDigits` 逐字节相同，33 行，

### 文本字面量的反斜杠

`''` 翻倍只解决引号，另一半是**转义字符本身**：MySQL 在单引号字面量里把反斜杠
当转义读，其它引擎（含开了 `NO_BACKSLASH_ESCAPES` 的 MySQL）把它当字面取。于
是同一份「翻倍」代码在两种引擎上含义相反——尾巴一个反斜杠就把收尾引号吃掉，字
面量与它后面那截语句黏在一起：

| 用户写的 | 旧渲染（MySQL 解析） | 后果 |
| --- | --- | --- |
| `x\` | `'x\'` … 未闭合 | 语法错误 |
| `\' OR 1=1 -- ` | `'\' OR 1=1 -- '` ⇒ 第 3 个引号闭合，`OR 1=1 -- ` 成 SQL | 注入 |
| `x\ny` | `'x\ny'` ⇒ 存成换行 | 静默改数据 |

这里的洞不是「少了一份规则」而是「有两份规则」：共享包的
`QuotedLiteral`（`tableprosql@v0.1.1/sqlgen.go:86-92`，MySQL 那条挂在
`dialect.go:27` 的 `quoteLiteralMySQL` 上）一直带 MySQL 分支，注释
写明了危害，`sqlgen_test.go:110-125` 五条断言守着；根仓 [../TableProGo/changes.go:200](file:///D:/tools/db/TableProGo/changes.go#L200)
委托它。fynequery 这边留的是本地那份副本
（[internal/db/changes.go:236](file:///D:/tools/db/fynequery/internal/db/changes.go#L236) 曾经自己拼
`''`），它比共享包少一条方言，所以修法是删掉拼接、改调
`tableprosql.QuotedLiteral`——两边同一个答案，测试也就一份。写路径（`valueLiteral`
→ `predicate`/`literals`）、过滤框（[internal/db/filters.go:66](file:///D:/tools/db/fynequery/internal/db/filters.go#L66)）、
INSERT 导出都走这一层。

`LIKE` 那一层叠在它上面：`contains` 用 `/` 做 `ESCAPE` 字符
（[internal/db/filters.go:35-38](file:///D:/tools/db/fynequery/internal/db/filters.go#L35)）正是为了避开
反斜杠的第二重含义，所以 `ESCAPE '/'` 在四个引擎上都原样通过字面量层（表驱动里
单列四条断言钉住）。也因此本仓的 pattern 是 `'%a\\b%'`（2 个反斜杠）而根仓那条
断言是 4 个——根仓的 `LikePattern` 自己会把反斜杠交给 `\` 转义，两边各自的
`ESCAPE` 选择不同，不是分叉。

负对照分两层，红出的都是**多算**而不是少算：先把方言参数写死成 `mysql`（等价于
所有引擎都翻倍反斜杠），4 条测试 8 条断言红，其中 4 条是新用例里「sqlite /
postgresql / oracle / sqlserver 必须原样取字」，另外 3 条是既有的 SQL Server
`N''` 前缀断言（`TestUpdateUsesKeyColumnsAndDialectQuoting`、
`TestInsertScriptExport`）——过度转义会改存进去的值，守卫必须是分方言的；再退回
本地那份只翻倍引号的实现，红 6 条（新用例 5 条 + 表内 1 条），红出来的字符串就
是上面表格里那三个。真库侧在契约套件写半区补了一条
`escaped text lands as the bytes that were typed`
（[internal/db/contract_test.go:767](file:///D:/tools/db/fynequery/internal/db/contract_test.go#L767)）：存 `a\'b\c` 与 `x\ny`
再读回逐字节比对，然后用过滤框搜 `\n` 必须恰好命中那一行——「引擎有没有把客户
端送出的字面量读成用户打的那些字节」只有服务端能答。

### 行数上限的截断探针

上限绑上之后，屏幕上「刚好 N 行」有两种解释：表里正好 N 行，或者后面还有行没被
取出来。行数本身分不出这两者——改之前这两条路径的状态栏字节完全相同（上限 3，
表里 3 行与表里 5 行都写「返回 3 行」）。所以 `Execute` 多要一行：窗口渲染成
`limit+1`，取回来真超过上限就裁回 `limit` 并把 `Truncated` 置真
（[internal/db/query.go:168](file:///D:/tools/db/fynequery/internal/db/query.go#L168)）。
这一位只在客户端自己注入的窗口上才会亮：语句自带 `LIMIT` 时按原样执行，多给几行
也不谎称上限生效（[internal/db/core.go:73](file:///D:/tools/db/fynequery/internal/db/core.go#L73)、
措辞在 [ui_query.go:473](file:///D:/tools/db/fynequery/ui_query.go#L473)）。

代价是一行。用 SQLite 文件库把「取 50 行」和「取 5050 行」各跑两轮，差值 ÷5000
≈ 1.9–2.0 µs/行；而一次 `Execute` 的地板值是 0.31–0.43 ms（两轮里两个探针臂各自
都当过一次更快的那个），多取一行落在往返噪声之下。

### 真机契约测试

`internal/db` 的单测证明方言表是完整的、渲染出的 SQL 与它声称的一致；但「目录
SQL 真机上答回来的形状，正好是客户端读回去的形状」这一层没法用单测伪造。
`internal/db/contract_test.go` 就是打真库的：`Databases`/`Tables`/`Columns`/
`ForeignKeys`/`TableIndexes`/`SearchInDatabase`/`TableName`/`TableDDL` 八条目录
读，加一页窗口互不重叠且合起来覆盖 fixture 的 25 行、行数上限真的截断、驱动
返回的字节渲染成文本而不是 `[112 97 …]`。fixture 是 parent/child + 外键 +
非唯一索引 + 视图——正好是 `dialect.go` 里每条目录查询冲着写的形状。

写路径同样有一组（`TestContractMySQLWritePath`/`TestContractPostgresWritePath`，
4 个子测试按网格的顺序共用一份 fixture）：把服务器自己返回的行原样交回
`ApplyChanges`，改一次名字；再把同一个值写第二次，断言它仍算「命中 1 行」——
这是 `execInTx` 那句「matched no row, nothing was committed」守卫的地基，而这条
规则每台 server 各答各的，SQLite 替不了 MySQL；第三条插一条重复主键，让批次在
第 2 条语句上死掉，回读确认第 1 条已写的行也没留下；第四条在回滚之后再存一次，
专抓 PostgreSQL 那个「current transaction is aborted」——事务没回干净的话，连接
之后每条语句都是红的。这一组刻意不断言值的 Go 类型：读回来的单元格是什么类型，
归驱动决定——lib/pq 把所有整数宽度解成 `int64`，go-sql-driver 的文本协议把无符号
BIGINT 解成 `uint64`、把 FLOAT 解成 `float32`、把字符串与 DECIMAL 解成包字节。
不管它是哪一种，原样回到 WHERE 里才是契约要验的事，而这只有真库说得上话。

它们默认跳过，并且把要设的变量打印出来：`FYNE_CONTRACT_MYSQL_HOST`（以及同族
的 `_PORT/_USER/_PASSWORD`）、`FYNE_CONTRACT_PG_HOST`。想让缺失变成失败，设
`FYNE_CONTRACT_REQUIRED=mysql,postgres`——CI 就是这么跑的，否则一个服务变量写错
会让契约悄悄退回绿色。跳过与失败这两条都有负对照：无 server 时 6 条全 skip，
设了 `REQUIRED` 或把 host 指到 `127.0.0.1:1` 都是红（6 条全红），不是 skip。

契约第一次被跑起来就抓到一处：MySQL 的索引目录查询只 SELECT 了 4 列，而
`scanIndexRow` 要 5 个落点，于是真 MySQL 上每次 `TableIndexes` 都在 scan 处报错
（[internal/db/dialect.go:291](file:///D:/tools/db/fynequery/internal/db/dialect.go#L291)
起的闭包）。已改：主键标志由 `INDEX_NAME = 'PRIMARY'` 在 SQL 里答，第三列把 `NON_UNIQUE`
取反。共享包里是同一段查询文本（`../TableProGo/tableprosql/catalog.go:218`），根仓的 scan
同样要 5 个落点（`../TableProGo/catalog.go:430`）——那一侧也已跟着 `e5dcded` 改完，本仓这个
闭包自 `tableprosql/v0.1.1` 起就是从共享包取语句，本地那份文本已经没有了。

CI 的 `contract` job 用 service 容器起 `mysql:8.0` 与 `postgres:16`，只跑
`./internal/db`（它需要 cgo 但不需要 UI 的 GL 头），并设
`FYNE_CONTRACT_WAIT_SECONDS=90`——镜像的健康检查可能在 MySQL 还处在「初始化用、
不监听网络」的临时实例阶段就转绿，这一段等待让它在 CI 里读起来是慢而不是坏，
本地手打错地址则照旧立刻失败。选 8.0 是因为它的默认认证
`mysql_native_password` 在未加密连接上必过；8.4 换成 caching_sha2 之后要不要再
配 TLS，本机没有 server 可以验，所以没在 CI 里赌这件事。诚实说一句：这一组契约
在我这台机器上一次都没真跑过（没有 server，也不便往你 WSL 的 docker 上拉镜像），
CI 那次 run 才是它第一次被执行——和 `release.yml` 里的 msys2 步骤同属「写了但还
没被真实 run 验证」的环节。

### 断开、翻页与目录读的三条收口

这一节记 ④⑤⑥ 三条：一次只读代码的风险盘点按严重度排到它们，共同点是「本机
`-race` 是绿的，所以没人看见」。三条各自配了守卫测试与负对照，负对照的口径是
「把守卫那一行改坏，测试必须变红」，红/绿数量写在每条后面。

**④ 读与断开的锁纪律。** `Conn.DB` 原来是导出字段：`Connect`/`Disconnect` 在
`Store.mu` 里写它，而 `dialect.go` 里 35 处目录读（27 处 `collectRows`、7 处
`collectRowsOn`、`browse_columns.go` 1 处）一处锁都不拿。跟 `Disconnect` 撞上的
读要么被 `-race` 报出来（本机实测报不到，见本节末尾），要么在两次取值之间撞上刚
被置空的句柄，把进程 panic 掉；更细的一
层在 `DeleteConnection`，它改之前先 `closePools()` 再 `delete(c.live, id)`（HEAD 的
`internal/db/store.go:161-170`），此时仍握着 `*Conn` 的在途查询会走
`perDatabasePool` 在那具已经没人认领的 Conn 上开一条新连接，服务端会话就此挂着。
现在三样状态都归 `Conn.mu`：主句柄（字段已收成私有 `db`，全仓再也写不出
`conn.DB`）、按库的会话池、以及 `closed` 这个「不再开新
会话」的标志；读只能经 `handle()`（[internal/db/core.go:68](file:///D:/tools/db/fynequery/internal/db/core.go#L68)）、
`isOpen()`（[:78](file:///D:/tools/db/fynequery/internal/db/core.go#L78)）与
`detach()`（[:89](file:///D:/tools/db/fynequery/internal/db/core.go#L89)）拿到，
锁序恒为 `Store.mu → Conn.mu`；`perDatabasePool`
（[internal/db/store_connect.go:89](file:///D:/tools/db/fynequery/internal/db/store_connect.go#L89)）
在 `Conn.mu` 内建池并 `PingContext`，`closed` 已置起就直接拒绝。守卫是
`internal/db/conn_lifecycle_test.go` 的 4 条（读撞上断开不 panic、断开后方言读
返回错误而不是崩溃、关闭的连接不能再注册池、读一律说「未连接」）。原来的测试只
覆盖「先断开再改表」，所以这条洞在本机一直是绿的；`recover` 计数是给「崩溃」这一
结果留的断言，至于这一对读写能不能被 `-race` 抓到，见本节末尾的实测——答案是不能，
所以钉住它的是那 4 条断言，不是检测器。

**⑤ 运行期间的翻页与取消归属。** 错的是顺序不是竞态：查询在途时翻页条仍可点，
第二轮 `runTracked` 会覆盖 `Client.cancelFn`，于是「取消」只停最新那个，旧的照旧
跑；两轮都往 UI 线程投递结果，后落地的说了算——网格是 A 页、页码条写着 B 页。
现在 `runTracked`（[ui_query.go:503](file:///D:/tools/db/fynequery/ui_query.go#L503)）
在 `busy` 期间直接拒绝第二轮并说明「已有查询在执行，请等待或点「取消」」，`setRunning`
（[:571](file:///D:/tools/db/fynequery/ui_query.go#L571)）把上一页/下一页/每页/分页
浏览与执行按钮一起灰掉，`cancelRun`（[:557](file:///D:/tools/db/fynequery/ui_query.go#L557)）
始终指向真正在跑的那一轮。守卫是 `ui_run_guard_test.go` 的 2 条：一条不碰数据库
地验拒绝与取消归属，一条通过真实控件验翻页条整条在途锁死、被拒的那次连页码都不
动。两者都用 `parkable` 把 `Client.dispatch` 换成测试自己逐条放行的队列，所以
「在途」是真的在途，不是靠 sleep 猜时间。

**⑥ 目录读的上下文与线程。** 审计给的口径是「事件线程上同步打库，且目录查询没有
ctx」：保存前生成语句、外键候选、过滤框取候选值、结构页四读、搜索遍历、导出 INSERT
脚本、schema 树加载都在 Fyne 线程里直跑，而 `collectRows` 压根没有 context 参数
——远端慢库等于窗口无响应，且点不到的「取消」按钮也救不了。改动分两层。内核侧：
`dialect` 里 8 个会打到服务器的闭包（`databases`/`schemas`/`tables`/
`completionObjects`/`columns`/`search`/`foreignKeys`/`indexes`，
[internal/db/dialect.go:25](file:///D:/tools/db/fynequery/internal/db/dialect.go#L25)）
与 33 处方言实现第一参数一律 `context.Context`，`collectRowsOn` 走
`db.QueryContext`（[:124](file:///D:/tools/db/fynequery/internal/db/dialect.go#L124)），
`poolFor`/`perDatabasePool` 的 `PingContext`、`ApplyChanges` 的 `BeginTx`/
`ExecContext`、`SearchObjects` 的循环内 `ctx.Err()` 检查同样跟着；`Execute`/
`ExecutePage`/`RunTableAction` 不再自己 `context.Background()`。UI 侧新增一个原语
`Client.background(work, after) cancel`
（[ui.go:405](file:///D:/tools/db/fynequery/ui.go#L405)）：把一轮服务器往返挪出事件
线程，并交回「放弃它」的把手；10 处调用点分布在 8 个文件，对话框把把手交给
`SetOnClosed`（4 处），所以关掉对话框不会留一条查询挂在服务器上。两条语义是设计
的核心：**被放弃的那一轮不上屏**（它的答案属于一个已经不存在的分片/过滤/对话框），
**已经答完的那轮照旧上屏**（下一轮排在它后面，超不过它）——不引入世代计数，靠
FIFO 投递就够，理由同 ⑤。`asyncRun` 关闭时它退化成同步调用，因此既有那批内联测试
一行都不用改。守卫共 8 条：`internal/db/catalog_ctx_test.go` 4 条（取消的 ctx 必
返回 `context.Canceled`、池被占满时调用方放弃能立刻脱身而不用等驱动、搜索遍历收到
放弃就停、被放弃的会话不会注册进 `conn.pools`），`ui_background_test.go` 4 条（工
作还挂着时调用方必须已经返回、被放弃的一轮零次上报、答完后才到达的取消仍上报一次、
内联路径按 work→after 顺序跑完）。

负对照与数量（都按「改坏一行→重跑→改回」做，改坏的行当场恢复）：

### 发版

本地一份：`task release`，产物名带 `git describe` 的版本与目标平台，同时
`-s -w` 剥符号（实测 76,375,647 → 45,992,448 字节，少 39.8%）并把 tag 注进
标题里的版本号。公开那份：`git tag v1.4.0 && git push --tags`，
`.github/workflows/release.yml` 出 Windows/Linux 两个产物、校验和与 Release 页。
窗口标题读的是 `main.appVersion`，源码里的默认值是给 `go run .` 看的，发布产物
一律由 `-X main.appVersion=${tag}` 覆盖——所以标题说的版本就是被发布的那个。
workflow 在上传前用两条断言替这个说法背书：`go version -m` 里能找到 tag，
`objdump -p` 里子系统必须是 `Windows GUI`（拿不带 flag 的产物做负对照，第二条会
失败）。Windows 那一行的 C 工具链步骤（`msys2/setup-msys2`）是唯一还没有真实
run 验证过的环节，它后面紧跟一步 `gcc --version`，环境不对就在那里失败，不会
静默产出空 release。

## 使用说明

页面布局对照 TablePro Go：左侧单一侧栏——「导航」标题（＋新建连接）、连接
下拉与连接/断开、测试/编辑/删除、对象过滤框（实时筛选已加载对象）、结构树、
底部历史栏；主区为**多查询标签页**（每页独立编辑器，可新建/关闭，共享结果
网格），标签下工具栏为 数据库 → 执行（高亮）→ 快捷键 → 行数上限 + 分页浏览 →
导出 → 主题；结果网格上方是翻页条（只在分页时出现），底部为单元格栏与
状态/操作工具条。

其他要点：

- **异步连接与查询**：连接握手、表目录加载、SQL 执行均在工作线程进行，界面不冻结；执行中可点「取消」中断长查询（fyne 2.6+ 的 fyne.Do 调度回主线程）
- **目录读可放弃**：结构页、结构操作（重命名/删除等发出的 DDL）、过滤框、单元格的外键候选、保存的生成语句与落库、搜索遍历、INSERT 导出、侧栏重载与数据库下拉刷新共 10 处，都经 `Client.background` 在工作线程上跑一轮服务器往返并带着 `context`；对话框关闭即放弃那一轮，它的答案不再上屏，已经答完的那轮则照常落地
- **线程归属**：当前连接 / 当前库 / 每页行数只归 UI 线程所有，工作线程拿的是启动时在 `c.mu` 内取到的快照；`TestQueryGoroutineUsesSessionSnapshot` 在 `go test -race` 下用一条慢查询 + 并发改写会话字段的守卫脚本钉住这条不变量
- **编辑器行号槽**：等宽 SQL 编辑器左侧带行号（禁用多行输入框实现，与编辑器同族同字号精确对齐）；长脚本在标签内滚动而非拉伸窗口，编辑时自动跟随光标行
- **查询标签**：多页独立编辑器（`Ctrl/Cmd+N` 新建、`Ctrl/Cmd+W` 关闭、
  `Ctrl/Cmd+1…9` 切到第 N 个），修改未执行的标签标题带 ● 标记、关闭前确认；
  切换标签时补全候选随活动页切换；关闭时各标签的 SQL 草稿与脏标记写入 `ui.json`，重启后完整恢复
- **主题**：工具栏可切 跟随系统/浅色/深色（即时生效并持久化）
- **历史写盘**：语句历史整份重写，但不是每执行一条就落盘——5 秒内连续执行只写一次，
  关窗时补齐剩下的尾巴（`TestHistoryWriteIsThrottled`）；进程被强杀最多丢这一个
  延迟窗口内的记录

1. **新建连接**：在侧栏顶部选择器旁点击「新建」，填写类型、主机、端口、账号等。
2. **测试**：点击「测试」验证连接参数。
3. **连接**：在下拉框选中连接后点击「连接」，侧栏中部会加载该库的结构树。
4. **查询**：在右侧编辑器输入 SQL（有自动补全），点击「执行」或按 `Ctrl+Enter`。
5. **浏览结构**：在侧栏结构树点击表名生成 SELECT 预览；右键表可查看结构 /
   删除 / 清空 / 重命名；右键数据库/模式点「新建表」拿方言建表草案；
   `Ctrl+P` 快速按名找表。服务器上的库多到翻不动时，在「编辑连接」的
   库过滤里写掩码（如包含 `APP*`、排除 `*_backup`）只留常用的那几个。
6. **编辑数据**：`SELECT * 单表` 结果可在网格底部工具条编辑单元格、插行、
   删行，确认后事务提交。
7. **翻页浏览大表**：勾选「分页浏览」，选好每页行数再执行 SELECT，用网格上方
   的上一页/下一页逐页读取（每页重新查库，不预读整表）。翻页条同时告诉你这一页
   的行序是否稳定：自动补了主键排序会写明，补不了会标 ⚠ 提醒可能重复/漏行。

## 说明

- 本模块为独立子模块，与根目录的 Wails 版本（`TableProGo`）可并存于同一
  仓库。共享逻辑已经下沉成两个独立模块——`tableprosql` 管各方言 SQL 文本与
  `ColumnType` 判定，`tableproxlsx` 管 Excel 渲染——两个客户端 pin 到同一组
  tag，改共享代码不再需要改两处各一份（这正是整型列曾在根仓导出成文本、
  Fyne 侧正常的原因）。
- **状态文件位置**：`connections.json`、`history.json`、`ui.json` 放在
  `os.UserConfigDir()/TableProGo`（Windows 即 `%AppData%\TableProGo`），
  与根版本同一目录、同一格式，因此保存的连接两边共享；代价是历史文件也
  是共享的，两个客户端同时开着会互相覆盖对方内存里那份日志。首次启动会把
  旧版留在 exe 旁的同名文件**复制**进配置目录（原文件保留，删用户数据不是
  本程序的权利）；配置目录已有同名文件时以配置目录为准。`TABLEPRO_STATE_DIR`
  可整体改道（便携安装、测试隔离），`go test` 就是靠它不碰真实连接
  （见 `main_test.go`）。
- 连接握手、目录浏览与 SQL 执行都在工作线程进行，结果经 `fyne.Do` 调度回 UI
  线程刷新；长查询可点「取消」中断，翻页取数走同一条异步路径。
